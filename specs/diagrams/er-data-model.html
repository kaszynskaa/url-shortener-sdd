Index Strategy

Indexes critical for redirect hot-path performance and analytics query patterns.

Table Index Name Columns Type Purpose
urls idx_urls_short_code short_code B-tree UK O(1) redirect lookup — primary hot path
urls idx_urls_user_id_created user_id, created_at DESC Composite List user's URLs sorted by recency
urls idx_urls_expires_active expires_at, is_active Partial TTL expiry sweeper job — WHERE is_active = true
clicks idx_clicks_url_id_ts url_id, clicked_at DESC Composite Time-series stats queries per short link
clicks idx_clicks_clicked_at clicked_at B-tree Global analytics rollups + partition pruning
audit_log idx_audit_event_ts event_type, occurred_at DESC Composite Security monitoring queries by event type
Partitioning: The CLICKS table SHOULD be range-partitioned by clicked_at (monthly) as it will grow into hundreds of millions of rows. Partition pruning ensures stats queries scan only the relevant months.

Migration strategy: Greenfield schema — no existing data migration for v1. Future changes MUST use CREATE INDEX CONCURRENTLY and non-locking ADD COLUMN … DEFAULT before SET NOT NULL.
